# Battlefield Babylon.js — 10 равных частей

**Канонический исходник** — `game.parts/01.part` … `10.part`: каждый содержит **121–122 последовательные строки** версии от 22.11.2026. Они не исполняются и не загружаются браузером по отдельности: JavaScript-замыкание `(async function(){...})();` сохраняется цельным в собранном `game.js`. Это предотвращает дополнительные 10 HTTP-запросов, ошибки области видимости и торможение Safari.

Сборка полностью локальная, на стандартном Node.js, без npm-пакетов, подписок и каких-либо сетевых подключений:

```sh
node babylon/tools/assemble-game-parts.cjs
node babylon/tools/assemble-game-parts.cjs --check
node --check babylon/game.js
node babylon/tests/test-ten-part-engineering.cjs
```

После любого изменения фрагмента необходимо пересобрать `game.js`. CI блокирует рассинхронизацию. Собранная версия по-прежнему запускается на iPhone Safari по стандартному URL `babylon/index.html`.

Нумерация — **строго техническая по строкам**; функции могут пересекать границу частей. Это не десять независимых сценариев и не десять отдельных движков.

Подход ZigZag: изучаем, повторно используем открытые движки, готовые анимации и существующие алгоритмы вместо платных SDK, а принимаем изменения только после проверок. Оригинальные GLB и ветка Three.js `main` не меняются.
