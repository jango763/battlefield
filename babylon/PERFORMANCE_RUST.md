# Battlefield — Rust / WebAssembly: резервный инструмент оптимизации

Статус: **согласовано к применению по необходимости; Rust пока не внедрён**.
Основной движок остаётся Babylon.js. Three.js (`main`) и утверждённый Вермахт не изменяются.

## Инструмент

- [erkamyaman/rust-anything](https://github.com/erkamyaman/rust-anything) — MIT.
- Назначение: записывать входы/выходы существующих вычислительных функций, переносить их на Rust и сравнивать поведение через `record`, `bridge`, `diff`, `gate`.
- Ориентирован на CLI, HTTP-серверы и библиотеки на JS/TS, Python, C, Go, Ruby, Java. **Для нашего браузерного Babylon.js требуется отдельная интеграция Rust → WASM с сохранением JS API**. Это не автоматический перенос движка, анимаций или визуального поведения.
- Документация установки: https://github.com/erkamyaman/rust-anything#quick-start. Установка **не требуется до выявления реального узкого места**.

## Когда применять

Сначала измерить на iPhone Safari и мобильном Chromium 10 / 30 / 50 / 100 бойцов: FPS и длительность кадров, JS/CPU на update, draw calls, память, размер и время загрузки GLB/текстур. Проверять на боевом сценарии с ИИ, построением и стрельбой, а не на пустой карте.

Кандидаты для Rust+WASM после подтверждённого CPU-узкого места:
1. Поиск пути и локальный обход препятствий большой армией.
2. Массовые вычисления ИИ / выбор целей и динамика отрядов.
3. Массовые пространственные запросы, если JS-профайлер выявит проблему.

Не переносить ради языка: рендер Babylon.js, WebGL, анимационные GLB/кости, текстуры, загрузку сети, интерфейс и одиночные мелкие функции. Для них сначала оптимизировать модели, LOD, материалы, draw calls, анимацию и частоты обновления.

## Обязательные ворота внедрения

1. **Базовый профиль:** записать исходные значения FPS, p95/p99 времени кадра, CPU-функции, память и размер загрузки.
2. **Отдельная ветка и тестовый стенд:** Rust-код и WASM никогда не заменяют JS до приёмки. Сохраняем откат/JS fallback.
3. **Поведенческая совместимость:** на детерминированных входах прогнать граничные случаи, пустые отряды, уничтожение солдата, перестроение «черепаха/полукруг», порядок команд, препятствия. Сверка rust-anything `record → bridge → diff → gate` применима к извлечённым чистым функциям. Для floating-point задать явно допустимую погрешность, не обещать побитной идентичности без необходимости.
4. **Безопасность:** `record` / `diff` действительно выполняют исходные функции много раз; запускать только копию с тестовыми данными, без секретов, сетевых/финансовых побочных эффектов и реальных записей.
5. **Результат:** мерить суммарное CPU+WASM время с учётом вызовов, передачи массивов и загрузки дополнительного WASM. Оставлять Rust только при устойчивом выигрыше без ухудшения времени первого действия и Safari.
6. **Приёмка:** подтверждение на настоящем iPhone Safari + одинаковая боевая механика; до этого не сливать в `main`.
